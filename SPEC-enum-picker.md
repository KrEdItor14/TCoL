# Spec: Цветные селекторы перечислений

## Objective

Заменить chip-кнопки в формах добавления снаряжения, создания квеста и добавления товара на селекторы в стиле выбора «Атмосфера контента» в настройках AI: кнопка с текущим значением открывает модальный список вариантов.

Пользователь должен видеть название выбранного значения, а в модальном списке каждый вариант должен иметь эмодзи, понятное название и цветной контур, соответствующий его редкости, состоянию или сложности. Цвет текста остаётся интерфейсным. Игровые значения, валидация, сохранение и обработчики форм не меняются.

Chip-кнопки остаются для:

- слотов снаряжения;
- типа квеста;
- активный chip остаётся залитым зелёным, как реализовано сейчас.

## Tech Stack

- Vanilla HTML, CSS и JavaScript.
- Основные исходники: `index.html`, `css/components.css`, `css/mobile.css`, `js/enum-picker.js`, `js/init-pickers.js`.
- Собранная копия приложения: `www/`, обновляется `npm run prepare:web`.
- Тесты: Node.js `assert` и `vm`.

## Code Style

Селектор получает конфигурацию вариантов, обновляет привязанное скрытое поле и отправляет событие `change`, поэтому потребители формы сохраняют текущее поведение.

```js
const picker = EnumPicker.create({
  targetId: 'gearNewRarity',
  variant: 'modal',
  title: 'Редкость',
  options: rarityOptions,
  defaultValue: 'common'
});

picker.selectValue('legendary');
// hidden input = 'legendary'; form listeners receive a bubbling change event.
```

- Идентификаторы значений (`common`, `good`, `normal`) и публичные ID элементов не меняются.
- Конфигурация вариантов остаётся в `js/init-pickers.js`; визуальное представление задаёт `js/enum-picker.js` и CSS.
- Для новых DOM-элементов использовать нативные `button` и `createElement`, не вставлять непроверенные значения через `innerHTML`.
- Цвет задаётся семантическим классом варианта, а не inline-стилем или повторяющимися hex-значениями.
- Модальное окно закрывается выбором варианта, кнопкой закрытия и нажатием на оверлей; фокус при открытии получает кнопка закрытия.

## Selection Contract

### Modal selectors

| Form | Field | Values | Outline colour |
|---|---|---|---|
| Экипировка | Редкость | ⚪ Обычная, 🟢 Необычная, 🔵 Редкая, 🟣 Эпическая, 🟡 Легендарная, 🟠 Уникальная, 🔴 Мифическая | Белый, зелёный, синий, фиолетовый, жёлтый, оранжевый, красный |
| Экипировка | Состояние | 🔴 Сломанное, 🟠 Повреждённое, 🟡 Потрёпанное, 🟢 Хорошее, 🔵 Надёжное, 🔷 Отличное, 🟣 Идеальное | Красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый |
| Квесты | Сложность | ⚪ Новичок, 🟢 Ученик, 🔵 Адепт, 🟣 Эксперт, 🟡 Мастер | Белый, зелёный, синий, фиолетовый, жёлтый |
| Магазин | Редкость | Те же семь значений редкости | Те же цвета редкости |

Кнопка-триггер показывает эмодзи и название текущего выбора. В открытом списке каждый вариант показывает те же данные, имеет цветной контур и доступное состояние выбора (`aria-pressed`).

### Preserved chips

| Form | Field | Required behavior |
|---|---|---|
| Экипировка | Слот | Существующие chip-кнопки и группировка сохраняются. Активная кнопка зелёная с заливкой. |
| Квесты | Тип | Две chip-кнопки, «Обычный» и «Рейд». Активная кнопка зелёная с заливкой. |

## Testing Strategy

- Добавить или расширить Node-тесты для `EnumPicker`, используя минимальный fake DOM, чтобы подтвердить:
  - modal-вариант открывается из кнопки-триггера;
  - заголовок и все ожидаемые варианты отображаются;
  - выбор обновляет hidden input и отправляет одно `change`-событие;
  - триггер отражает новое значение;
  - варианту назначается нужный цветной класс и `aria-pressed`;
  - modal закрывается после выбора, по кнопке закрытия и по оверлею.
- Проверить, что слоты и тип квеста продолжают использовать режим chip и активный chip имеет существующее зелёное состояние.
- Запустить `node tests/settings-ui.test.js` как регрессию для эталонного AI-пикера и затем `npm run test:all`.
- После `npm run prepare:web` проверить, что `www/` содержит те же HTML, CSS и JavaScript изменения.

## Boundaries

- **Always:** сохранять ID и значения hidden-полей; отправлять bubbling-событие `change`; использовать доступные нативные кнопки, видимый фокус и `aria-modal`; проверять мобильный вид от 320 px; запускать тесты до завершения.
- **Ask first:** добавление зависимостей; изменение формата игровых данных или сохранений; изменение логики создания предметов, квестов или товаров; изменение CI или Capacitor-конфигурации.
- **Never:** менять семантику редкости, состояния, сложности, слотов или типа квеста; превращать слоты или тип квеста в модальные селекторы; удалять существующие тесты; вручную расходиться между исходниками и `www/`; перезаписывать несвязанные текущие изменения пользователя.

## Success Criteria

1. В формах экипировки редкость и состояние выбираются через модальный список в стиле выбора атмосферы AI.
2. В форме квеста сложность выбирается через такой же модальный список, а тип остаётся двумя chip-кнопками.
3. В магазине редкость выбирается через такой же модальный список.
4. Каждый вариант содержит требуемые эмодзи и название, а его контур имеет ровно заданный цвет.
5. Текст вариантов сохраняет интерфейсный цвет, поэтому цвет не является единственным носителем смысла.
6. Слоты экипировки остаются chip-кнопками, а их активное состояние и активный тип квеста остаются залитыми зелёным.
7. Выбор в каждом selector обновляет существующее hidden-поле и не меняет дальнейшую логику формы.
8. Модальные списки доступны с клавиатуры, имеют корректный фокус и закрываются по трём обозначенным сценариям.
9. Все тесты проходят, а `www/` синхронизирован командой `npm run prepare:web`.
