# Spec: Канонический контракт слотов экипировки

## Objective

Устранить рассинхрон между исходными модулями, собранным runtime и интерфейсом для exclusive-слотов экипировки. Пользователь должен видеть и использовать один и тот же порядок и набор слотов во всех точках приложения:

`Голова`, `Лицо`, `Тело`, `Верхняя одежда`, `Перчатки`, `Ноги`, `Ступни`, `Обувь`, `Рюкзак`.

Каждый из них хранит ровно один предмет. Аксессуары остаются отдельной группой с несколькими предметами в слот.

Этот модуль создаёт базовый контракт для последующих модулей `save-slot-migration` и `face-slot-ai`. Он не меняет семантику сохранений и не добавляет AI-правила, кроме предоставления канонического списка, которым они будут пользоваться.

## Tech Stack

- Vanilla HTML, CSS и JavaScript без зависимостей.
- Исходники: `data/constants.js`, `data/default-state.js`, `js/equipment.js`, `js/equipment-core.js`, `js/init-pickers.js`.
- Собранный runtime: `js/runtime.js`, создаётся из модулей командой `build-runtime.bat`.
- Распространяемые копии: `www/` и `android/app/src/main/assets/public/`, создаются из исходников командой `npm run prepare:web`.
- Проверки: Node.js `assert` и `vm` в `tests/`.

## Project Structure

```text
data/constants.js       → Единственный источник списка, порядка, иконок и legacy-алиасов слотов
 data/default-state.js   → Новое игровое состояние с пустыми exclusive-слотами
js/equipment-core.js    → Переходы экипирования одного предмета в exclusive-слот
js/equipment.js         → Рендер exclusive-слотов и создание предметов
js/init-pickers.js      → Chip-picker, строящий варианты из констант
js/runtime.js           → Генерируемый единый браузерный bundle, не редактируется вручную
index.html              → Контейнеры UI экипировки и полей создания предмета
tests/                  → Контрактные и регрессионные Node-проверки
www/                    → Генерируемая web-копия
android/app/src/main/assets/public/ → Генерируемая Capacitor-копия
```

## Code Style

Канонические игровые названия определяются только в `data/constants.js`; потребители строятся от этих констант, а не дублируют массивы или объекты по строковым литералам.

```js
const EQUIP_SLOTS = [
  'Голова', 'Лицо', 'Тело', 'Верхняя одежда',
  'Перчатки', 'Ноги', 'Ступни', 'Обувь', 'Рюкзак'
];

const equipment = Object.fromEntries(EQUIP_SLOTS.map(slot => [slot, null]));
```

- Названия слотов и их порядок сохраняются ровно как в каноническом списке.
- `Лицо`, `Перчатки` и `Рюкзак` являются exclusive-слотами и не попадают в `ACCESSORY_SLOTS`.
- `SLOT_ICON` содержит иконку для каждого значения `ALL_SLOTS`.
- Ручные дубликаты слотов в исходных модулях запрещены.
- `js/runtime.js`, `www/` и Android public assets редактируются только генераторами.

## Testing Strategy

- Добавить контрактную Node-проверку, которая загружает `data/constants.js` и `data/default-state.js` в `vm` и подтверждает:
  - точный порядок девяти `EQUIP_SLOTS`;
  - `Лицо`, `Перчатки` и `Рюкзак` присутствуют ровно по одному разу;
  - `ALL_SLOTS` содержит все exclusive- и accessory-слоты;
  - `SLOT_ICON` покрывает все `ALL_SLOTS`;
  - `defaultState().equipment` имеет ровно ключи `EQUIP_SLOTS`, все со значением `null`.
- Дополнить UI-проверки, если потребуется, чтобы picker добавления экипировки строился из канонического списка и показывал `Лицо`, `Перчатки` и `Рюкзак` в exclusive-группе.
- После пересборки проверять, что `js/runtime.js` и его копии в `www/` содержат тот же контракт.
- Запускать focused-проверки, затем `npm run test:all`. Известные внешние сбои полного набора фиксируются отдельно, но не скрываются и не обходятся отключением тестов.

## Boundaries

- **Always:** использовать `EQUIP_SLOTS`, `ACCESSORY_SLOTS`, `ALL_SLOTS` и `SLOT_ICON` как единый контракт; сохранять `Перчатки` и `Рюкзак` как exclusive-слоты; пересобирать runtime и generated-копии; добавлять регрессионные тесты; перед изменениями учитывать существующие незакоммиченные правки.
- **Ask first:** изменять формат save envelope или версию схемы; добавлять зависимости; менять CI, Capacitor-конфигурацию, баланс мощности или механику аксессуаров.
- **Never:** вручную редактировать `js/runtime.js`, `www/` или Android public assets; удалять данные пользователя или тесты; менять названия канонических слотов; относить `Лицо` к аксессуарам; перезаписывать несвязанные правки пользователя.

## Success Criteria

1. В `data/constants.js` существует единственный канонический список из девяти exclusive-слотов в указанном порядке.
2. `Перчатки` и `Рюкзак` присутствуют в константах, состоянии по умолчанию, picker UI, рендере экипировки и собранном runtime.
3. `Лицо` присутствует как exclusive-слот во всех тех же точках и отображается с иконкой `🕶️`.
4. `defaultState().equipment` и отображение `renderSlots()` используют один и тот же контракт, без вручную продублированных списков.
5. Для каждого `ALL_SLOTS` есть иконка, а аксессуары остаются multi-equip слотами.
6. Контрактные и связанные UI-проверки проходят; после `npm run prepare:web` web- и Android-копии синхронизированы с исходниками.
7. Никакие миграции существующих сейвов и AI-ограничения не реализуются в этом модуле, они остаются задачами последующих утверждённых модулей.
